# v1.15.3 - 2026-07-24 - PM2 Docs Correction

> **PM2 Docs Correction** — `STATUS.md`, `CONTEXT.md`, `ROLLBACK_PLAN.md`, `docs/DEPLOYMENT.md`, and
> `docs/governance/REPOSITORY_HANDOFF_CONFIG.md` all documented the booking API as running under

## How This Was Found

Discovered while verifying real deploy authorization as part of Slice 7 of
`REPO_PUSH_SUPER_PROMPT_HANDOFF_SKILL_INTEGRATION_PLAN` (an AntBrainOS vault workflow-integration
effort). A read-only `systemctl status booking-platform` check (run specifically to confirm safe
deploy/restart procedure before any real deployment authorization) showed the unit inactive since
2026-06-16, contradicting the public health check (`{"status":"ok"}` at `/api/health`) and every
doc's description. `pm2 list` / `pm2 describe booking-platform` confirmed the real running process.
